# 機體 Roguelike — v0.1

日系人形機體、開闊地形、六角格向量移動的 roguelike。手機直向瀏覽器優先，TypeScript + Canvas 2D + Vite，零遊戲引擎相依。

**線上版（手機直接開）**：https://darkbearlab.github.io/mech_roguelike/
（第一次需要到 repo 的 **Settings → Pages → Source** 選 **GitHub Actions**，之後推到 `main` 就會自動部署。）

規格書：[`docs/spec-v0.1.md`](docs/spec-v0.1.md)

## 目前進度：第 2 步（手感測試）

規格 §12 的建置順序寫明「第 2 步跑起來就該先讓設計者試手感，再往下走」，所以停在這裡：

| 步驟 | 狀態 |
|---|---|
| 1. 六角座標與繪製、觸控盤骨架 | ✅ |
| 2. 向量移動與驅動型態（單機、無敵人） | ✅ **← 請試手感** |
| 3. 朝向與射界、視線 | 朝向與前方三面已完成（地面驅動的加速限制要用）；射界、視線未做 |
| 4. 行動點、透支、熱量 | 帳務規則已完成並測試（轉向、散熱、切換驅動、加速產熱都要用）；緊急切斷未做 |
| 5. 單一武器與命中公式 | 未做。`combat.json` 已放好規格給過的常數，右盤的武器鍵顯示成本但不能按 |
| 6. 敵人三態與喊話預告 | 未做。引擎已能讓敵人跑同一套 宣告 → 位移 → 行動 |
| 7. bot 基線數據 | 移動版已有（見下），勝率與命中率等第 5 步 |

### 怎麼試

- 右上 **⚙** 開調參面板：切換四台試驗機（履帶／步行／噴射／步行＋噴射），直接改推力、阻力、極速、產熱、質量，
  面板會即時算出「淨推進、幾回合到極速、滑行幾回合停、制動幾回合停」。改過的值存在手機上，重新整理還在。
  **「複製調整值」**把你調好的數字變成一段 JSON —— 貼給我，我寫回 `src/data/`。
- 左盤（① 加速）**按住**看那個選項的整條路徑與之後的滑行，**放開**送出；滑出按鍵再放開 = 取消。
  地圖上的琥珀色小圈是八個選項各自的落點。
- 右盤（② 行動）在位移之後才能按，按「待機」結束回合。
- 點地圖看那一格的地形、高度、距離；拖曳平移，◎ 回中，下一次加速宣告會自動回中。
- 網址參數：`?chassis=jt1`（tk1 / wk1 / jt1 / hy1）、`?seed=123`。
- 桌機：QWE / ASD 六向、空白 巡航、X 制動、← → 轉向、C 散熱、V 切換驅動、Enter 待機。

## 與規格不同、或規格沒寫而我先決定的地方

**這一節是給設計者看的。**每一條都是暫定，數字全在 JSON 裡，規則的部分改起來也都集中在一個函式。

1. **§3.2 表格的數字在 §3.1 的順序下動不了。** 表格的履帶 accel 4 / drag 4、步行 6 / 6，
   而 §3.1 是「先加速、再扣阻力」—— 同一回合完全抵銷，地面機體永遠停在原地
   （`tests/movement.test.ts` 有一條測試專門釘住這件事）。
   我**保留 §3.1 的順序不動**，改數字：讓「淨推進 = accel − drag」重現表格的 4 / 6 / 12，
   並把地面驅動的 drag 拉高到「不推就在兩回合內停下」（§3.2 的意圖）：

   | 驅動 | accel | drag | 極速 | 淨推 | 到極速 | 滑行停 | 制動停 | 每推熱 |
   |---|---|---|---|---|---|---|---|---|
   | 履帶 | 14 | 10 | 20 | 4 | 5 回合 | 2 回合 | 1 回合 | 1 |
   | 步行 | 15 | 9 | 18 | 6 | 3 回合 | 2 回合 | 1 回合 | 3 |
   | 噴射 | 14 | 2 | 40 | 12 | 4 回合 | 20 回合 | 3 回合 | 6 |

   副作用是地面驅動可以「一個反推就停下」、「隨時改主意」，這正是規格想要的步行手感；
   代價是 accel 這一欄不再直接代表驅動的個性（淨推才是）。另一條路是「推進的回合不扣阻力」，
   那樣表格原本的數字就能用，但步行機要六回合才能掉頭 —— 我覺得那違背「幾乎沒有慣性」，所以沒選。
2. **`drives.json` 放推力 `thrust` 而不是 `accel`**，實際 accel 照 §3.2 的公式 `round(thrust / mass × SUB)` 算。
   這樣質量才有意義：複合機 HY-1 比單驅動機重 5，同一具推進器裝上去 accel 就少 1。
3. **`chassis.json` 的 `drive` 改成陣列 `drives`**，第一個是出擊時的模式。腿＋推進器的機體就是兩個元素。
4. **轉向在行動階段（位移之後）。** §5 的順序是「加速宣告 → 位移 → 行動」，轉向是行動（§4.1 表格）。
   結果是：地面驅動**這回合轉的向，決定下回合能往哪推** —— 步行那一面免費轉向，
   要拿來瞄準（第 3 步起朝向決定射界）還是拿來準備下一步，是每回合的取捨。噴射沒有這個問題，這正是它的價值。
5. **步行轉第二面以上**：規格只說「每回合免費 1 面」。我讓超出的每一面照 `actions.json` 的轉向收 1 AP（與履帶同價）。
   若要的是「最多 1 面」，需要在 `turnRule` 加一個上限欄位（目前沒有，因為規格沒說）。
6. **0 AP 的事（免費轉向、待機）在背債時照做**；「還清前不能做新的行動」只擋要花 AP 的行動。
7. **配額在自己的階段開始時才扣抵債務**，不是回合開始時 —— 這樣透支之後整個敵人階段與世界階段都背著債
   （不散熱、第 5 步起命中 −10%），脆弱視窗才看得見。沒用完的 AP 在階段結束時作廢，不累積。
8. **過熱停機**：熱量夾在上限；在自己的階段中過熱時，這個階段剩下的行動當場取消，再加上下一個完整階段。
   停機的階段強制巡航，阻力照常（噴射會繼續飄）。停機中再加熱不會延長停機。
9. **地形阻力取出發那一格。** 阻力在位移之前結算，那一刻機體踩的是出發格。
10. **撞擊（§11.6 待決）**：停在撞上之前那一格的中心、速度歸零。事件裡帶著撞擊前的速度，日後算撞擊傷害從那裡接。
11. **制動也產熱**（反推同樣燒推進器），按實際減掉的速度計。
12. **切換驅動保留速度**，但下一次位移會被新驅動的極速夾住 —— 噴射 4.0 格/回切回步行，下回合直接掉到 1.8。
    這等於一個很猛的緊急煞車，可能需要規則處理（例如切換後極速逐回合下降）。

## 指令

```bash
npm install
npm run dev        # http://localhost:5173（手機同網段可用 --host 顯示的網址開）
npm test           # 規則層、資料檔、分層規則（core/ 不得 import render/ui）
```

## 架構

沿用 PMC 已驗證的分層：

```
src/
  core/        純邏輯。不 import render/ 或 ui/，不碰 DOM、canvas、Math.random（tests/architecture.test.ts 會檢查）
    hex.ts       flat-top axial 座標、cube 距離、六角直線、次格精度 SUB = 10 —— 全專案唯一的一把尺
    rules.ts     讀 data/*.json 成有型別的 Rules、驗證、覆寫（調參面板與 bot 的 A/B 用）
    map.ts       地圖（odd-q 位移座標的逐列字串 → axial）
    state.ts     GameState、Unit、Command、GameEvent
    movement.ts  §3.1 的六步解算、側向加速、驅動輪廓 —— 預測與實際走同一段程式碼
    economy.ts   AP 配額、透支、債務、熱量
    order.ts     解算順序模組（§11.1）：目前只有循序制，換成同時制就是換一個 ResolutionOrder
    engine.ts    回合引擎：checkLegal() / applyCommand() —— 規則層唯一的入口
    nav.ts       導航規劃（bot 與日後的敵人 AI 共用）、繞過稜線的距離場
    rng.ts       可播種 xoshiro128**
  render/      canvas 繪製、攝影機、位移動畫
  ui/          觸控盤、儀表、調參面板、輸入接線
  data/        drives / chassis / actions / terrain / combat / ui .json、maps/*.json
tests/         core/ 全覆蓋
bot/           無介面自動對局
```

## bot 基線（`npm run bot`，每台 30 場，種子 1..30）

一場 = 在試驗場上從隨機起點開到 12～24 格外的隨機目標。自動駕駛只用玩家能用的指令。

| 機體 | 抵達率 | 平均回合 | 格/回合 | 熱量峰值 | 撞擊/場 | 勝率 | 命中率 |
|---|---|---|---|---|---|---|---|
| TK-1 陸龜（履帶） | 100% | 11.7 | 1.50 | 1.0 | 0 | — | — |
| WK-1 野犬（步行） | 100% | 11.2 | 1.57 | 3.0 | 0 | — | — |
| JT-1 燕（噴射） | 100% | 6.4 | 2.78 | 20.2 | 0 | — | — |
| HY-1 隼（步行，不切換） | 100% | 11.6 | 1.51 | 3.0 | 0 | — | — |

讀法：純移動下噴射每回合淨增 3 熱（推 +6、被動 −3），熱量還構不成壓力 —— 要等第 5 步射擊的 +6 / +20 疊上來。

CI（`.github/workflows/deploy.yml`）在每次 push 到 `main` 時跑：型別檢查 → 測試與覆蓋率 → bot 煙霧測試 → 建置 → 部署 → **線上健檢**。
