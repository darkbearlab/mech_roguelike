## 回合

每回合依序：

1. **玩家階段**：左盤（機動宣告：轉向＋加速）做一次 → 機體位移 → 右盤（行動）
2. **敵人階段**：每台敵機同樣流程，依陣列順序（決鬥場起有了會還手的敵機，見「決鬥」）
3. **世界階段**：被動散熱、狀態計時、勝敗判定

解算順序抽成可替換的模組（`src/core/order.ts`），目前是循序制：玩家先手。
畫面上照事件順序一段一段播：你開槍 → 敵機轉向、移動 → 敵機開槍，然後回到你的機動宣告。

（2026-09-11 驗證過「分段制」—— 全員先宣告、一起移動、再一起行動 —— 結論與數據見文末「實驗紀錄」。
先維持循序制；等有多台敵人時再用同一套方法測一次。）

## 移動

### 狀態

- 位置**永遠在格子中心**。
- 速度 = **速度方向**（六個方向之一）＋ **速率**（整數，格/回合）。
- **機首**另外存，與速度方向完全獨立。

### 左盤：機動宣告（轉向＋加速）

設計者 2026-09-11：**轉向也在移動之前決定**，和加速一起送出。右盤（行動）不再轉向。

- 最上排是**轉向**：⟲ 左轉／機首／右轉 ⟳。點幾下就轉幾面（最多半圈）；中間那格顯示轉完之後的機首與代價，點它 = 不轉。
- 下面三排是加速：方向鍵**跟著轉完之後的機首排**，上面那顆永遠是「前」；中間一整排是**確認鍵**（roguelike 的「空過」鍵）。
- 往一個方向**點幾下，就是這回合在那個方向加速幾**，按確認一次送出轉向＋加速。
  一回合只選一個方向；點別的方向 = 改選；同一方向點超過上限 = 歸零。
- 什麼都不點直接確認 = 不轉、不加速。
- 結算順序：**先轉**（照驅動收費、扣速度）→ **再加速**（相對新機首）→ 位移。
  轉向不能透支；AP 花在轉向上，右盤能用的就少了（履帶轉一面就沒得開火）。

**能點幾下**看加速方向相對**機首**的扇區（前／左右前／左右後／後），每種機體不同。

**點下去的效果**看加速方向相對**目前速度方向**的夾角：

| 相對速度方向 | 結果 |
|---|---|
| 同向 | 速度 + 點數，最多到極速 |
| 偏 60° | 速度 − 折損60 + 點數，速度方向改成加速方向 |
| 偏 120° | 速度 − 折損120 + 點數，速度方向改成加速方向 |
| 反向 | 速度 − 點數（煞車），扣到 0 就靜止 |
| 靜止中 | 直接往那個方向，速度 = 點數 |
| 沒點 | 速度 − 衰減 |

結果夾在 0 ～ 極速。確認後沿速度方向筆直走「速率」格。

### 設計者的範例（高速機）

極速 5；前 3、左右前 2、左右後 0、後 3（反推器）；偏 60° 折損 1。

1. 靜止、機首朝北，**往前點 3 下** → 往北 3 速
2. **往左前點 2 下** → 3 − 1 + 2 = **4 速**，速度方向變西北（機首還是北）
3. 下一回合的機動：**左轉 60°**（機首跟上速度方向，這台機體轉向折損 1 → 3 速）＋**往後點 3 下** → 3 − 3 = **0**，靜止

沒先轉機首的話煞不了車：速度的正後方在機首的右後，這台推不動。

### 轉向的代價

- 花 AP（依驅動：履帶每面 1 AP、步行每回合第一面免費、噴射免費）。
- **依機體類型，轉向也可能扣當下的速度**（高速機每面 −1）。

### 暫定、待討論

- **地形目前完全不影響移動**（設計者：先無視任何地形限制，之後慢慢討論）。擋路的只有地圖邊緣與其他機體。
- **撞擊**：停在撞上之前那一格、速度歸零；事件帶著撞擊前的速度，日後算撞擊傷害從那裡接。
- 切換驅動時，速度超過新驅動的極速就當場夾住。

## 右盤與 AP

- 射擊、裝填、散熱、換驅動等行動，各花不等的 AP。**成本先沿用現在的表，要實際測**（`actions.json`）。
- 右盤原本轉向的兩格空著，**留給未決的功能**。
- 轉向的 AP 在左盤的機動宣告就先扣了（見「移動」）。
- **AP 用完，或主動按「待機」，就推進回合。**
- **透支**：手上還有 AP 時可以做比它貴的行動 —— 行動照常結算，然後這個階段結束；
  不夠的部分**直接從下一回合的 AP 扣**（扣不完的繼續帶著）。透支上限 `apDebtCap`。
- 背著債的世界階段不被動散熱。

## 熱量（沿用，待討論）

- 左盤每點一下產熱（依驅動）；行動產熱；世界階段被動散熱。
- 到上限就過熱停機：這個階段剩下的取消，再加上下一個階段不能加速也不能行動（慣性照常衰減）。

## 射擊（設計者 2026-09-11：先一把基本步槍）

- 右盤「射擊」打**選中的目標**：行動階段自動選命中率最高的；點地圖上的靶（桌機 Tab）= 改選，
  這一回合有效，同時跳出命中率的明細。
- **射界看武器**（`weapons.json` 的 `arcDegrees`，以機首為中心）：步槍 180°，正側面那一排算在內。
  射程是 cube 距離（同一把尺）。行動階段地圖上亮的扇形就是打得到的格子 —— 與規則是同一條判斷；較亮那圈是有利射程。
- 右側武器面板之後再做；現在一台一把。

### 命中率

```
命中率 = 火控適性             火控 × 武器類別（fireControls.json）—— 不是武器本身的命中
       + 有利射程加成         距離落在武器的有利射程內
       − 追蹤 × 相對速度      自己與目標的相對位移差（主因；追蹤是火控的）
       − 重量 × 自己的速度    越重的武器高速時越不準
       − 角度                 偏離機首越多越難打（每 30° 一格；現在全 0）
       − 掩體                 地形還不影響任何事，先 0
       − 電戰                 還沒有電戰系統，先 0
夾在 5%～95%（combat.json）
```

- **相對速度** = 目標的速度向量減自己的速度向量的長度（同一把 cube 尺）：同向同速互打最準、迎面或交錯最難打；
  自己停下來時只剩目標的速度。
- **基礎是「火控 × 武器類別」的適性**（設計者：聽起來荒謬，但比較好平衡 —— 只要看一張表；加一種新武器，就在每套火控補一格）。
  追蹤係數（算提前量）也放在火控，這是實作時的判斷，要改回武器只是搬一個欄位。
- 加速階段射擊鍵上的「≈」是照「這樣加速之後」的位置算的：靶在玩家行動之後才動，
  所以只要不再轉向，就是行動階段按下去的命中率。
- 擲骰走 GameState 裡的種子亂數：同一個種子、同一串指令，永遠同一個結果。

| 步槍 | |
|---|---|
| 射程 | 6 格，有利射程 2–4 格（+10） |
| 射界 | 180° |
| 重量 | 2 |
| 傷害 | 10（靶的耐久 20 = 兩發） |
| 彈匣 | 6 |
| 射擊 | 1 AP、+6 熱 |
| 裝填 | 2 AP、+2 熱（配額 1 的機體一定透支） |

標準火控：步槍適性 75、追蹤 8。停著打有利射程內的固定靶 = 85%；自己 3 速打靜止的靶 = 85 − 24 − 6 = 55%。

### 靶

- `chassis.json` 裡 `role: "TARGET"` 的機體：**固定靶**（不動）與**靶機**（極速 2，沿巡邏點來回）。
  沒有武器，也不算敵人（打光不會結束對局）。
- 地圖的 `units` 開局就在場上；檢查點的 **SPAWN** 鉤子在觸發時生出一個（規則層認得的第一種鉤子效果）。
- 靶由引擎自己跑：玩家待機之後直接回到玩家。

## 決鬥（設計者 2026-09-11：第一台會還手的敵機）

- 決鬥場 `duel_01`：開闊地、一台敵機，**先打爆對方的贏**。碎石只是地標（地形目前不影響任何事）。
- 被打中只扣耐久（100），歸零就輸；部位損傷留給之後的左儀表板。
- 敵機跟玩家用**同一套規則**：同樣的加速、AP、熱、步槍與火控；它的每個行動都走和玩家同一段合法性檢查與結算程式碼。
  地圖上寫 `ai: "DUEL"` 的單位就是敵機（`src/core/ai.ts`）。
- 敵機的腦袋：
  - **還遠**：機首轉向要去的地方（付得起的面數），往你身邊的有利射程開（導航）
  - **近了**：每個付得起的轉向 × 每個合法的加速都推演一回合，挑分數最低的 ——
    移動完你還在它的射界內（開火時機首已經定了）＞ 距離落在有利射程 ＞ 自己打得準、你打不準
    （你在它之後宣告，看得到它停在哪 —— 假設你會轉過去面向它）；這回合反正打不到時，也先把機首擺向你
  - **行動**：打得中（≥ 25%）就打；打光了裝填；太熱散熱；其餘待機（轉向在機動宣告裡）
  - 喊話預告先不做：它的速度箭頭就是預告（有慣性，下一步大致猜得到）
- 對手可以在 ⚙ 換成四台試驗機的任何一台（網址 `?rival=jt1`）；最佳紀錄（最少回合的勝場）依對手分開記。
- 畫面：
  - 你的耐久在儀表上
  - 上方那一行是對手的耐久與說明，分出勝負就顯示結果與命中統計
  - 你（或加速階段預測的落點）頭上的紅字「⚠62%」是對手打你的命中率。它用對手現在的位置與速度估，對手在你之後才動，所以只是參考
  - 被打中的提示等子彈飛到才跳

**bot 的觀察（兩邊用同一顆 AI）**：用現在的數值，兩邊停著、或同向同速平行開、互相對射，是最划算的打法 ——
相對位移差對兩邊一樣，重量 × 自身速度卻只扣開火的那一方，所以「開快 = 難被打中」的好處被自己打不準抵掉還不夠。
命中率普遍落在 7～8 成，一場約 17 回合。要讓速度成為防禦，得在命中公式裡做出不對稱（例如分開「自己的速度」與「對方的速度」的係數）——
這是設計決定，先記在待討論清單。

## 跑道與檢查點（情境測試，之後的新手教學）

地圖可以帶一條**跑道**：依序的檢查點（`src/data/maps/track_01.json` 的 `course`）。

- 檢查點是一個區域：中心格 + 半徑（預設 1 = 7 格）。
  - **PASS（通過）**：這回合的位移路徑碰到區域內任何一格就算
  - **STOP（停車）**：位移結束時停在區域內、速度 0
- 只有「下一個」算數，先碰到後面的不會跳關；一次長距離位移可以連續通過好幾個。
- 每個檢查點有一句 **hint**：畫面上方那一行顯示目前目標與這一步要做什麼 —— 當新手教學時，這就是每一步的教學。
- 跑完 = 對局結束，記錄回合數；每條跑道、每台機體的最佳紀錄存在手機上。

### 事件鉤子（設計者 2026-09-11：檢查點可以當事件的鉤子）

每個檢查點可以掛 `hooks`：`[{ when, type, ...其他欄位 }]`。

- `when`：**ACTIVATE** = 它成為下一個目標時；**REACH** = 通過／停住時（預設）。
  每個檢查點的 ACTIVATE、REACH 各發一次、依序發，一次衝過好幾個也一樣。
- `type`：由訂閱的系統解讀，只負責在對的時機發出來（`COURSE_HOOK` 事件）。
  - 介面認得 **MESSAGE**（`text` = 跳出的旁白）
  - 規則層認得 **SPAWN**（生出一個靶：`chassis`、`col`、`row`，可選 `id`、`facing`、`patrol`）
  - 其他 type 原封不動發出來，之後的新手教學、開放按鍵、換規則之類的系統接上就能用，不必改跑道的格式。

### 基礎跑道（`track_01`）

11 個檢查點，每段練一件事：起步 → 直線加速 → 右轉 60° → 再右轉（要先轉機首）→ **停車框** → 靜止起步 → 蛇行 ×4 → **終點停車**。
建議機體是噴射（設計者的高速機）；⚙ 可以換機體比較。

### 射擊場（`range_01`）

5 個檢查點：起步 → **停車框**（左右各一個固定靶，停著打最準）→ 行進射擊（跑道兩側 3 個固定靶）
→ 通過第 4 個檢查點時，終點外側生出一台**巡邏靶機**（SPAWN 鉤子）→ **終點停車**。
上方那一行顯示擊毀數；完賽時列出擊毀數與命中率。建議機體是步行（慢一點比較好瞄）。

## 介面

- 直式手機。地圖滿版，下方左盤（加速）、右盤（行動＝座艙）。
- 右盤的佈局由機型的座艙定義；機型差異應該落在「能知道什麼」，而不是「按鈕在哪」。
- 地圖上機體周圍的數字 = 每個方向能點幾下（左盤跟著機首，這個讓人對得上地圖）。
- 射擊：打得到的靶頭上寫命中率，選中的有白色準星；射擊鍵寫著命中率與成本，打不到就寫原因。
  開槍有曳光（沒打中會擦過去）與飄字；同一批事件裡開槍之後的移動排在曳光之後播。

### 之後：左右儀表板（設計者 2026-09-11 補充，**不是這一輪**）

機體的狀態不放在中間的主畫面，而是畫面左右各一組儀表板：

- **左儀表板**：機體當前狀態 —— 部位損傷、熱、武器損失之類
- **右儀表板**：切換武器、準備非戰鬥裝備、準備技能之類
- **手機**：從側邊拖到中間看
- **電腦**：常駐在左右兩側

## 實驗紀錄（2026-09-11，bot，兩邊同一顆 AI）

**方向**（設計者）：做的是 roguelike —— 玩家要過得了關，儘管有困難；不是機器人狗鬥遊戲。
以**笨重機體為主**（六方向加速、極速 2～3），**輕型狗鬥機為點綴**；交戰距離可以長；路上撒半掩體、全掩體。

**分段制**（全員宣告 → 一起移動 → 一起行動）會不會帶來 Aeronautica 式的讀心博弈？

- 只把結算分開：會預測對手去向的 AI 開始大量移動，但移動完常常打不到（能開火的比例 9 成 → 3～6 成），
  沒有任何移動的打法贏得了「停著、原地轉身開火」。原因：沒動的一方看著你停在哪、原地轉過去再開火；
  180° 射界又大；命中公式的重量項只扣開火的一方。
- 再加上「轉向在移動前宣告」＋射界 ≤ 90°：**慢機體**（步行）出現讀心博弈 —— 讀者對坐著 95～100%、雙方邊走邊打不和局；
  但**快機體**（噴射）變成長時間亂舞（和局 38～75%），履帶（轉向吃 AP）在某些射界互打全和局。
- 空曠處：繞圈本身不是問題（步行也一直走，但照樣分出勝負）；問題是「繞圈卻打不到」，出在機動力遠大於追瞄能力、
  或轉向太貴的時候。沒有地標可以卡位也是原因之一 —— 地形、掩體、目標會自然打破僵局。

**笨重機體＋長射程（12）＋掩體**（重機極速 2／3、有利 4～8、半掩體 −25、全掩體擋視線不能穿；3 張隨機對稱圖 × 20 種子 × 2 座位）：

- 味道是**慢節奏的陣地槍戰**：第 3 回合進射程，之後十幾回合對射，一場 17～20 回合（主要由耐久 100／傷害 10 決定，可調）；
  會用掩體的一方在密集地形 54% 的回合躲在掩體後，贏不會用的 65%。極速 2 的重機 0% 和局；極速 3 在掩體間晃，和局 17～21%。
- 長射程下射界幾乎不影響（6～8 格外甩不掉 180°）；分段制反而削弱掩體的價值（不知道對手會在哪、掩體該擋哪一邊），
  窄射界＋密集掩體會讓大家躲著不打（讀者互打 98% 和局）。
- 輕型噴射對重機：循序 25～38%、分段 33～50% —— 用不到掩體、自己又打不準，要當點綴得給它自己的工作。

**決定**：轉向搬到左盤（機動宣告，版面更緊湊、右盤專心開火），**維持循序制**；分段制等有多台敵人時再測。
